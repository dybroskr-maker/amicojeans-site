01

오더 번호 — 26FW-AB-012

번호 하나가 시즌·거래처·순번을 모두 담습니다. 사진·파일·진행 상태가 전부 이 번호에 붙습니다.

  • 시즌 표기 — 26FW(가을겨울) · 26SS(봄여름)
  • 순번은 거래처별로 001부터 매깁니다. 거래처는 자기 번호만 보므로 힇갈리지 않습니다.
  • 번호는 오더가 생성되는 순간 시스템이 자동으로 붙입니다. 손으로 적지 않습니다.

02

샘플 단계

대표님이 쓰시는 말 그대로 1차샘플 · 2차샘플로 확정합니다. 오더 번호 뒤에 단계 코드를 붙입니다.

확정. 대표님 2차 회신(8/22) — 별도 의견 없음 = 수용. 생산 전 확인(-PP)·판매용(-SS)·선적(-SH)도 위 코드 그대로 확정합니다. 다섯 단계 전부 확정 상태이며, 화면에는 한국어 병기로 표기합니다.

03

거래처 코드와 시범 등록

  • 거래처 코드 = 회사명 영문 이니셜 2자. 예: 에이비패션 → AB, 씨디컴퍼니 → CD
  • 이니셜이 겹치면 뒤에 숫자를 붙입니다. 예: AB, AB2
  • 시범 거래처는 대표님이 직접 등록하십니다. 관리자 화면에 「거래처 추가」를 먼저 만들어 두겠습니다.
  • 거래처 등록 시 받는 항목 — 회사명 · 이니셜 코드 · 담당자 이름 · 담당자 이메일 · 거래 품목

04

누가 무엇을 보는가

거래처 화면에는 원가와 공장 이름이 아예 전달되지 않습니다. 화면에서 가리는 것이 아니라 데이터가 넘어가지 않게 막습니다.

05

로그인 — 두 갈래

06

계정 5개

  • 내부 계정 5개를 만듭니다. 대표 1 + 관리자·직원 4를 기본으로 잡되, 배분은 대표님이 화면에서 바꾸실 수 있습니다.
  • 대표 또는 관리자가 이름과 비밀번호를 직접 등록·변경합니다. 개발자를 거치지 않습니다.
  • 접근레벨 3단 — 대표(전부) / 관리자(계정 관리 포함) / 직원(담당 오더 + 원가·마진 열람)
  • 퇴사·교체 시 해당 계정만 끄면 즉시 차단됩니다. 다른 사람 비밀번호를 바꿀 필요가 없습니다.

07

첫 화면 — 현황 대시보드

대표님 지시대로 관리가 필요한 것을 전부 한 화면에 올립니다. 로그인하면 이 화면이 먼저 열립니다.

대시보드에 올라가는 것

  • 지연 · 오늘 입고 · 확인 대기 — 손이 필요한 건만 위로 올립니다
  • 이번 주 납기 목록
  • 시즌 합계(오더 수 · 수량 · 원가/마진) — 거래처에는 넘어가지 않습니다
  • 오더 보드 4칸 — 샘플 · 확정 · 생산 · 출고. 카드를 끌어 옮기면 상태가 바뀝니다
  • 거래처 목록 · 스타일/샘플 · 계정 설정 진입
