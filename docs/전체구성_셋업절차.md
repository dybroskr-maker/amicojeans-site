> 둘(Cloudflare·Supabase)인 편이 낫다. ③ 두 배포처 모두 $0이라 비용 차이가 없다.

## 0. 런타임 선택 규칙 — 값보다 먼저 본다

**런타임은 프레임워크가 정한다. 값은 동률일 때만 결정한다.**

이 규칙이 없으면 프로젝트마다 다른 기준으로 고르게 되고, 나중에 왕복 이전을 하게 된다.

| 앱의 성격 | 맞는 런타임 | 이유 |
|---|---|---|
| Next.js SSR (예: dybros-app) | Vercel | Next.js 제작사의 네이티브 플랫폼. 어댑터를 끼우면 새 버전 기능 지원 여부에 발이 묶인다 |
| 정적 SPA + Supabase (예: 아미코 거래처룸) | Cloudflare | 어댑터가 낄 자리가 없다. 잠금이 없어 어디로든 옮겨진다 |

### 아미코에 적용하면

거래처룸은 **정적 SPA + Supabase**다. 서버 렌더링이 필요한 화면이 없고, 로그인 뒤 화면이라 SEO도 무관하다.
공개 사이트도 순수 HTML·CSS·JS다. 둘 다 Cloudflare가 맞다.

**그래서 아미코에서 진짜 위험한 결정은 호스팅이 아니라 프레임워크다.**

- 아미코에 **Next.js를 도입하지 않는다.** 지금 코드는 순수 HTML·JS라 어디로든 옮겨진다
- Next.js를 얹는 순간 Cloudflare 어댑터 의존이 생기고, 지원이 늦는 기능이 나오면 Vercel로 되옮겨야 한다
- 도입이 꼭 필요해지면 그것은 **런타임 재검토 사안**이다. 프레임워크만 슬쩍 바꾸지 않는다

### 옮길 때의 원칙 (양쪽 프로젝트 공통)

비용이 오른다는 것은 트래픽이 늘었다는 뜻이고, 그때가 플랫폼을 흔들기 가장 나쁜 때다.
왕복 비용은 편도의 두 배가 아니다 — 갈 때 재배선·회귀 검증을 하고, 돌아올 때 같은 일을 또 한다.

대응 순서를 고정한다. **① 원인 분해 → ② 파일 이그레스면 저장소만 분리 → ③ 캐시·설정 튜닝 → ④ 런타임 이전은 마지막.**
런타임 이전의 사유는 비용 절감이 아니라 공급자 리스크(요금제·정책 변경)다.

## 1. 가져오는 것 / 가져오지 않는 것

### 가져온다 — 자동화 3종뿐

| 파일 | 하는 일 |
|---|---|
| `agent-worker.yml` | 이슈에 라벨 → 구현 → PR |
| `agent-review.yml` | PR 검증 → 조건 충족 시 자동 머지 |
| `gate.yml` | PR 필수 체크 |

**파일 구조와 점화 방식만 가져오고, 내용은 전부 아미코용으로 새로 쓴다.**
DYBROS 고유 규칙(22단계 코어 · `money.ts` · `supabase/` 경로 규약 · `docs/MAP.md` · T2 판정표)은
한 줄도 옮기지 않는다. 옮기면 아미코 저장소에서 존재하지 않는 파일을 참조하다 워커가 헤맨다.

### 가져오지 않는다

폴더 구조 · 저장소 · Supabase 프로젝트 · 로컬 작업 트리 · 문서 체계 · 시크릿 · 라벨 운용 이력.

### 이름을 나눈다

| 구분 | DYBROS | 아미코 |
|---|---|---|
| 자동화 명칭 | DYLOOM | **AMILOOM** |
| GitHub | `dybroskr-maker/dybros-app` | `amicojeans/site` · `amicojeans/room` |
| DB | DYBROS Supabase 조직 | **amicojeans Supabase 조직**(신규) |
| 배포 | Vercel | **Cloudflare Pages (공개 사이트 · 거래처룸 둘 다)** |
| 로컬 | `~/dev/dybros-app` | `~/amico/room` |

**DYLOOM이라는 말을 아미코 쪽에서 쓰지 않는다.** 아미코 자동화는 AMILOOM이다.
배포 플랫폼도 겹치지 않는다 — DYBROS는 Vercel, 아미코는 Cloudflare. 물리적으로 섞일 수 없다.

**아미코를 DYBROS의 Vercel 팀에 얹지 않는다.** 기술적으로는 가능하고 추가 비용도 없지만,
계정·청구서 분리 지시와 양도양수 요건에 정면으로 어긋난다.

## 2. 구성

```
amicojeans/site     public    Cloudflare Pages    공개 사이트 (v0.4에서 Pages→Cloudflare)
amicojeans/room     public    Cloudflare Pages    거래처룸 (정적 SPA)
                                                  └ Supabase(amicojeans 조직)
GitHub                                            저장소 · AMILOOM 자동화 전용 (배포 안 함)
```

**Vercel을 쓰지 않는다.** 서버 렌더링이 필요한 화면이 없기 때문이다(0장 규칙).
Hobby는 상업 용도가 금지되고 Pro는 사용자당 월 $20이 붙는데, 같은 값을 Cloudflare Pages가 무료로 한다.

**Cloudflare를 쓰는 이유**
- 상업 사용 허용 · 대역폭 사실상 무제한(사진이 많은 사이트에 유리)
- 무료 플랜에서 월 500회 빌드, 프로젝트당 커스텀 도메인 100개, 파일 2만 개
- PR마다 미리보기 배포가 자동으로 생성된다 → 대표가 머지 전에 확인할 URL이 생긴다
- DYBROS가 쓰는 Vercel과 플랫폼이 달라 계정·청구서가 섞일 수 없다
- 배포처가 하나라 양도양수 시 넘길 계정이 줄어든다

**저장소를 public으로 두는 이유** — 비밀은 코드가 아니라 DB에 있다.
Supabase 공개 키는 브라우저 노출 전제로 설계된 키이고, 방어선은 RLS다(→ `거래처룸_권한설계.md`).
대신 **저장소에 실제 거래처 데이터·이메일·계약 파일을 커밋하지 않는다.**

## 4. 누가 무엇을 하는가

### A. 길호님만 가능 — 계정 4건

| 할 일 | 어디서 | 값 |
|---|---|---|
| GitHub 조직 생성 | https://github.com/organizations/plan | 이름 `amicojeans` · Free |
| Supabase 조직 + 프로젝트 | https://supabase.com/dashboard/new | 조직 `amicojeans` · 프로젝트 `amico-room` · 리전 Seoul |
| Cloudflare 계정 + Pages 연결 | https://dash.cloudflare.com/sign-up | 저장소 `amicojeans/site` · `amicojeans/room` 둘 다 연결 |
| GitHub 시크릿 등록 | 저장소 Settings → Secrets → Actions | `CLAUDE_CODE_OAUTH_TOKEN` · `SUPABASE_DB_URL` |

토큰·비밀번호 입력은 대신 하지 않는다.

### B. 채팅이 실행 (길호님 손 0)

1. `dybroskr-maker/amicojeans-site` → `amicojeans/site` 이전
2. **공개 사이트 Cloudflare Pages 이관 · GitHub Pages 비활성화**(v0.4 신규)
3. `amicojeans/room` 저장소 생성 + 골격
4. `supabase/0001_schema.sql` — 테이블 7종 + RLS 정책
5. 거래처룸 정적 SPA 뼈대 — 매직링크 로그인 + 오더 목록(읽기 전용)
6. AMILOOM 3종 설치 — 두 저장소 각각, 내용은 아미코용으로 새로 작성
7. 라벨 생성 — `auto-t0` · `auto-t1` · `needs-hub`

### C. 맥 코드세션 (주 1회 이하)

```
gh repo clone amicojeans/room ~/amico/room
```

T2 배치(인증 경로 · RLS 정책 · 쓰기 기능)만 여기서 받는다.

## 7. 혼동 방지 규칙 (위반 시 되돌린다)

- 아미코 저장소에서 DYBROS 파일·경로·문서를 참조하지 않는다
- DYBROS 저장소에 아미코 파일을 두지 않는다 (지금 `amicojeans-site` 가 그 상태 — 6장 2번에서 해소)
- 두 회사의 이슈를 한 저장소에서 다루지 않는다
- Supabase 프로젝트를 DYBROS 조직 안에 만들지 않는다
- 아미코를 Vercel에 배포하지 않는다 (DYBROS 전용 플랫폼)
- **아미코에 Next.js를 도입하지 않는다** (0장 — 도입은 런타임 재검토 사안)
- 로컬 트리를 섞지 않는다 (`~/amico/` vs `~/dev/`)
- 아미코 쪽에서 "DYLOOM" 이라는 말을 쓰지 않는다
