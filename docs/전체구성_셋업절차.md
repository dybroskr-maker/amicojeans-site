# 아미코 전체 구성 · 셋업 절차 v0.1

작성 2026-08-21 · DYBROS Co.
목적: 공개 사이트(완료)에서 거래처룸까지, 무엇을 어디에 만들고 누가 하는지 한 장으로 확정한다.

---

## 1. 전체 구성 — 저장소 2개, 서비스 3개

```
① amicojeans-site   public   GitHub Pages          공개 사이트 (완료·운영 중)
   └ 컬렉션 · 프로젝트 · 브랜드 · 설문 · 문서

② amico-room        private  Vercel + Supabase     거래처룸 (신규)
   └ 로그인 · 오더 카드 · 사진 · 권한(RLS)

서비스:  GitHub(저장소·자동화) · Supabase(DB·인증·파일) · Vercel(배포)
```

**왜 저장소를 나누는가**
- 공개 사이트는 소스가 공개돼도 아무 문제가 없고, 거래처룸은 스키마·정책이 들어가므로 공개하면 안 된다.
- 배포처가 다르다(Pages vs Vercel). 한 저장소에 섞으면 공개 사이트 문구 하나 고칠 때마다 거래처룸이 재배포된다.
- 나중에 아미코로 넘길 때 **거래처룸만 먼저** 넘기거나, 공개 사이트만 남기는 선택이 가능해진다.

**계정 명의** — 지금은 DYBROS 계정으로 만들고 v1.0 오픈 시 아미코 계정으로 이전한다.
대표 계정 생성을 기다리면 진도가 멈춘다. 이전이 쉬운 구조(저장소 Transfer · Supabase 조직 이전 · Vercel 팀 이전)로 짓는 것으로 대신한다.

---

## 2. 로컬 폴더 — 필요한 만큼만

**로컬 클론은 필수가 아니다.** 저장소 골격 생성, 문서, 공개 사이트 수정은 전부 채팅(GitHub 커넥터)과
DYLOOM(클라우드 실행)으로 처리된다. 맥이 필요한 것은 **코드세션이 T2 배치를 돌 때뿐**이다.

거래처룸은 인증·RLS·다파일 설계라 T2다. 따라서 클론 1회는 필요하다.

```
~/dev/
 ├ dybros-app/        (기존)
 └ amico-room/        (신규 — 코드세션 작업 폴더)
```

`amicojeans-site` 는 로컬에 두지 않는다. 단일 HTML이라 DYLOOM으로 충분하고,
로컬 사본이 있으면 어느 쪽이 최신인지 헷갈리는 사고만 는다.

## 3. 누가 무엇을 하는가

### A. 채팅이 실행 (길호님 손 0)

1. `amico-room` 저장소 생성 (private)
2. 골격 푸시 — `README.md` · `AGENTS.md` · `CLAUDE.md` · `docs/` · `.gitignore`
3. `supabase/0001_schema.sql` — 테이블 7종 + RLS 정책 (권한설계 문서 기준)
4. Next.js 최소 골격 — 로그인 화면 · 오더 목록(읽기 전용) 뼈대
5. DYLOOM 3종(`agent-worker` · `agent-review` · `gate`) — 두 저장소 모두
6. 라벨 생성 — `auto-t0` · `auto-t1` · `needs-hub`

### B. 길호님만 가능 (계정·비밀번호·토큰)

| 할 일 | 어디서 | 값 |
|---|---|---|
| Supabase 프로젝트 생성 | https://supabase.com/dashboard/new | 이름 `amico-room` · 리전 **Northeast Asia (Seoul)** |
| Vercel에 저장소 연결 | https://vercel.com/new | `amico-room` import |
| GitHub 시크릿 등록 | 저장소 Settings → Secrets → Actions | `CLAUDE_CODE_OAUTH_TOKEN` · `SUPABASE_DB_URL` |
| Vercel 환경변수 등록 | Vercel 프로젝트 Settings → Environment Variables | `NEXT_PUBLIC_SUPABASE_URL` · `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` |

토큰·비밀번호 입력은 대신 하지 않는다. 값의 출처와 붙여넣을 칸은 그때 링크로 안내한다.

### C. 맥 코드세션 (주 1회 이하로 몰아서)

```
gh repo clone dybroskr-maker/amico-room ~/dev/amico-room
```

이후 T2 배치(인증 경로 · RLS 정책 · 오더 카드 쓰기)를 코드세션이 받는다.
T0/T1(문구·화면 수정·공개 사이트)은 계속 DYLOOM행이다.

## 4. 순서

| 순 | 내용 | 담당 | 선행 |
|---|---|---|---|
| 1 | 대표 설문 회수 → 공개 사이트 v0.3 반영 | 채팅 | — |
| 2 | `amico-room` 저장소 + 골격 + 스키마 | 채팅 | — |
| 3 | Supabase·Vercel 생성, 시크릿 4종 등록 | 길호님 | 2 |
| 4 | 스키마 적용 · 로그인 화면 배포 확인 | 채팅 | 3 |
| 5 | 코드세션 클론 → 오더 카드 읽기 전용 구현 | 코드세션 | 4 |
| 6 | 거래처 1곳 시범 계정 발급 · 오더 5건 투입 | 길호님+채팅 | 5 |
| 7 | 쓰기 개방(사진·코멘트·상태 변경) | 코드세션 | 6 한 시즌 |

2번과 3번은 같은 날 끝난다. 5번부터가 실제 개발이다.

---

## 5. 하지 않는 것

- 공개 사이트를 Vercel로 옮기지 않는다 (Pages로 충분하고, 배포 분리가 방어선이다)
- `amicojeans-site` 를 로컬에 클론하지 않는다
- 거래처룸 저장소를 public으로 만들지 않는다
- 원가 계산·정산·재고를 1차에 넣지 않는다 (권한설계 문서 8절)
