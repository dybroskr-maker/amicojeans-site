# 아미코 전체 구성 · 셋업 절차 v0.2

작성 2026-08-21 · DYBROS Co.
**대표 지시 2026-08-21: DYBROS에서 가져오는 것은 자동화(워크플로)뿐이다. 폴더·저장소·DB·계정은 혼동될 여지를 남기지 않는다.**

---

## 1. 가져오는 것 / 가져오지 않는 것

### 가져온다 — 자동화 3종뿐

| 파일 | 하는 일 |
|---|---|
| `agent-worker.yml` | 이슈에 라벨 → 구현 → PR |
| `agent-review.yml` | PR 검증 → 조건 충족 시 자동 머지 |
| `gate.yml` | PR 필수 체크 |

**파일 구조와 점화 방식만 가져오고, 내용은 전부 아미코용으로 새로 쓴다.**
DYBROS 고유 규칙(22단계 코어 · `money.ts` · `supabase/` 경로 규약 · `docs/MAP.md` · T2 판정표)은
한 줄도 옮기지 않는다. 옮기면 아미코 저장소에서 존재하지 않는 파일을 참조하다 워커가 헤맨다.

### 가져오지 않는다

폴더 구조 · 저장소 · Supabase 프로젝트 · 로컬 작업 트리 · 문서 체계 · 시크릿 · 라벨 운용 이력.
아미코 것은 전부 새로 만든다.

### 이름을 나눈다

| 구분 | DYBROS | 아미코 |
|---|---|---|
| 자동화 명칭 | DYLOOM | **AMILOOM** |
| GitHub | `dybroskr-maker/dybros-app` | `amicojeans/site` · `amicojeans/room` |
| Supabase | DYBROS 조직 | **amicojeans 조직**(신규) |
| 로컬 | `~/dev/dybros-app` | `~/amico/room` |
| 배포 | Vercel | GitHub Pages |

**DYLOOM이라는 말을 아미코 쪽에서 쓰지 않는다.** 같은 이름을 두 곳에서 쓰면
"어느 저장소의 워커가 도는가"가 매번 헷갈린다. 아미코 자동화는 AMILOOM이다.

## 2. 인프라는 둘뿐이다 — GitHub · Supabase

```
amicojeans/site     public   GitHub Pages     공개 사이트 (이전 예정)
amicojeans/room     public   GitHub Pages     거래처룸 (정적 SPA)
                                              └ Supabase(amicojeans 조직) 호출
```

**Vercel을 쓰지 않는다.** Hobby 플랜은 상업 용도가 금지되어 있고, 팀을 따로 파면 월 $20이 붙는다.
거래처룸은 서버 렌더링이 필요 없는 화면이라 Vercel이 하는 일이 없다.
인프라 판이 하나 줄면 혼동도 그만큼 준다.

**거래처룸 저장소를 public으로 두는 이유** — 비밀은 코드가 아니라 DB에 있다.
Supabase의 공개 키(publishable)는 애초에 브라우저에 노출되는 전제로 설계된 키이고,
실제 방어선은 RLS 정책이다(→ `거래처룸_권한설계.md`).
대신 **저장소에 실제 거래처 데이터·이메일·계약 파일을 커밋하지 않는다.** 이건 규칙으로 못 박는다.

---

## 3. 로컬 폴더

```
~/amico/
 └ room/        거래처룸 작업 트리 (코드세션 전용)
```

- `~/dev/` 아래에 두지 않는다. DYBROS 트리와 물리적으로 분리한다.
- 폴더 이름에 `dybros` 가 들어가지 않는다.
- **공개 사이트(`site`)는 로컬에 클론하지 않는다.** 단일 HTML이라 AMILOOM으로 충분하고,
  로컬 사본이 있으면 어느 쪽이 최신인지 헷갈리는 사고만 는다.

## 4. 누가 무엇을 하는가

### A. 길호님만 가능 — 계정 3건

| 할 일 | 어디서 | 값 |
|---|---|---|
| GitHub 조직 생성 | https://github.com/organizations/plan | 이름 `amicojeans` · Free |
| Supabase 조직 + 프로젝트 생성 | https://supabase.com/dashboard/new | 조직 `amicojeans` · 프로젝트 `amico-room` · 리전 Northeast Asia (Seoul) |
| GitHub 시크릿 등록 | 각 저장소 Settings → Secrets → Actions | `CLAUDE_CODE_OAUTH_TOKEN` · `SUPABASE_DB_URL` |

토큰·비밀번호 입력은 대신 하지 않는다.

### B. 채팅이 실행 (길호님 손 0)

1. `dybroskr-maker/amicojeans-site` → `amicojeans/site` 로 이전(Transfer) · Pages 재활성화
2. `amicojeans/room` 저장소 생성 + 골격
3. `supabase/0001_schema.sql` — 테이블 7종 + RLS 정책
4. 거래처룸 정적 SPA 뼈대 — 매직링크 로그인 + 오더 목록(읽기 전용)
5. AMILOOM 3종 설치 — 두 저장소 각각, 내용은 아미코용으로 새로 작성
6. 라벨 생성 — `auto-t0` · `auto-t1` · `needs-hub`

### C. 맥 코드세션 (주 1회 이하)

```
gh repo clone amicojeans/room ~/amico/room
```

T2 배치(인증 경로 · RLS 정책 · 쓰기 기능)만 여기서 받는다.
T0/T1(문구 · 화면 · 공개 사이트)은 AMILOOM행이다.

## 6. 혼동 방지 규칙 (위반 시 되돌린다)

- 아미코 저장소에서 DYBROS 파일·경로·문서를 참조하지 않는다
- DYBROS 저장소에 아미코 파일을 두지 않는다 (지금 `amicojeans-site` 가 그 상태 — 2번에서 해소)
- 두 회사의 이슈를 한 저장소에서 다루지 않는다
- Supabase 프로젝트를 DYBROS 조직 안에 만들지 않는다
- 로컬 트리를 섞지 않는다 (`~/amico/` vs `~/dev/`)
- 아미코 쪽에서 "DYLOOM" 이라는 말을 쓰지 않는다
