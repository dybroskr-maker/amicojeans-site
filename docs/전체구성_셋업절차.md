# 아미코 전체 구성 · 셋업 절차 v0.3

작성 2026-08-21 · DYBROS Co.
**대표 지시 2026-08-21: DYBROS에서 가져오는 것은 자동화(워크플로)뿐이다. 폴더·저장소·DB·계정은 혼동될 여지를 남기지 않는다.**

> v0.3 정정 — 거래처룸 호스팅을 GitHub Pages → **Cloudflare Pages** 로 변경.
> 근거: GitHub Pages 이용 정책은 온라인 비즈니스·상업용 SaaS 호스팅을 허용하지 않고,
> 비밀번호 등 민감한 거래에 쓰지 말 것을 명시한다. 로그인 기반 거래처룸이 여기 걸린다.
> 공개 사이트(회사 소개·컬렉션)는 상거래 촉진 목적이 아니므로 Pages에 그대로 둔다.

## 1. 가져오는 것 / 가져오지 않는 것

### 가져온다 — 자동화 3종뿐

| 파일 | 하는 일 |
|---|---|
| `agent-worker.yml` | 이슈에 라벨 → 구현 → PR |
| `agent-review.yml` | PR 검증 → 조건 충족 시 자동 머지 |
| `gate.yml` | PR 필수 체크 |

**파일 구조와 점화 방식만 가져오고, 내용은 전부 아미코용으로 새로 쓴다.**
DYBROS 고유 규칙(22단계 코어 · `money.ts` · `supabase/` 경로 규약 · `docs/MAP.md` · T2 판정표)은
한 줄도 옮기지 않는다. 옮기면 아미코 저장소에서 존재하지 않는 파일을 참조하다 워커가 헤맨다.

### 가져오지 않는다

폴더 구조 · 저장소 · Supabase 프로젝트 · 로컬 작업 트리 · 문서 체계 · 시크릿 · 라벨 운용 이력.

### 이름을 나눈다

| 구분 | DYBROS | 아미코 |
|---|---|---|
| 자동화 명칭 | DYLOOM | **AMILOOM** |
| GitHub | `dybroskr-maker/dybros-app` | `amicojeans/site` · `amicojeans/room` |
| DB | DYBROS Supabase 조직 | **amicojeans Supabase 조직**(신규) |
| 배포 | Vercel | GitHub Pages(공개) · **Cloudflare Pages**(거래처룸) |
| 로컬 | `~/dev/dybros-app` | `~/amico/room` |

**DYLOOM이라는 말을 아미코 쪽에서 쓰지 않는다.** 아미코 자동화는 AMILOOM이다.
배포 플랫폼도 겹치지 않는다 — DYBROS는 Vercel, 아미코는 Cloudflare. 물리적으로 섞일 수 없다.

## 2. 구성

```
amicojeans/site     public    GitHub Pages        공개 사이트 (이전 예정)
amicojeans/room     public    Cloudflare Pages    거래처룸 (정적 SPA)
                                                  └ Supabase(amicojeans 조직)
```

**Vercel을 쓰지 않는다.** Hobby는 상업 용도가 금지되고 Pro는 사용자당 월 $20이 붙는데,
거래처룸에는 서버 렌더링이 필요한 화면이 없다. 같은 값을 Cloudflare Pages가 무료로 한다.

**Cloudflare Pages를 쓰는 이유**
- 상업 사용 허용 · 대역폭 사실상 무제한(사진이 많은 사이트에 유리)
- 무료 플랜에서 월 500회 빌드, 프로젝트당 커스텀 도메인 100개, 파일 2만 개
- PR마다 미리보기 배포가 자동으로 생성된다 → 대표가 머지 전에 확인할 URL이 생긴다
- DYBROS가 쓰는 Vercel과 플랫폼이 달라 계정·청구서가 섞일 수 없다

**거래처룸 저장소를 public으로 두는 이유** — 비밀은 코드가 아니라 DB에 있다.
Supabase 공개 키는 브라우저 노출 전제로 설계된 키이고, 방어선은 RLS다(→ `거래처룸_권한설계.md`).
대신 **저장소에 실제 거래처 데이터·이메일·계약 파일을 커밋하지 않는다.**

## 3. 로컬 폴더

```
~/amico/
 └ room/        거래처룸 작업 트리 (코드세션 전용)
```

- `~/dev/` 아래에 두지 않는다. 폴더 이름에 `dybros` 가 들어가지 않는다.
- **공개 사이트(`site`)는 로컬에 클론하지 않는다.** AMILOOM으로 충분하다.

## 4. 누가 무엇을 하는가

### A. 길호님만 가능 — 계정 4건

| 할 일 | 어디서 | 값 |
|---|---|---|
| GitHub 조직 생성 | https://github.com/organizations/plan | 이름 `amicojeans` · Free |
| Supabase 조직 + 프로젝트 | https://supabase.com/dashboard/new | 조직 `amicojeans` · 프로젝트 `amico-room` · 리전 Seoul |
| Cloudflare 계정 + Pages 연결 | https://dash.cloudflare.com/sign-up | 저장소 `amicojeans/room` 연결 |
| GitHub 시크릿 등록 | 저장소 Settings → Secrets → Actions | `CLAUDE_CODE_OAUTH_TOKEN` · `SUPABASE_DB_URL` |

토큰·비밀번호 입력은 대신 하지 않는다.

### B. 채팅이 실행 (길호님 손 0)

1. `dybroskr-maker/amicojeans-site` → `amicojeans/site` 이전 · Pages 재활성화
2. `amicojeans/room` 저장소 생성 + 골격
3. `supabase/0001_schema.sql` — 테이블 7종 + RLS 정책
4. 거래처룸 정적 SPA 뼈대 — 매직링크 로그인 + 오더 목록(읽기 전용)
5. AMILOOM 3종 설치 — 두 저장소 각각, 내용은 아미코용으로 새로 작성
6. 라벨 생성 — `auto-t0` · `auto-t1` · `needs-hub`

### C. 맥 코드세션 (주 1회 이하)

```
gh repo clone amicojeans/room ~/amico/room
```

T2 배치(인증 경로 · RLS 정책 · 쓰기 기능)만 여기서 받는다.

## 7. 혼동 방지 규칙 (위반 시 되돌린다)

- 아미코 저장소에서 DYBROS 파일·경로·문서를 참조하지 않는다
- DYBROS 저장소에 아미코 파일을 두지 않는다 (지금 `amicojeans-site` 가 그 상태 — 2번에서 해소)
- 두 회사의 이슈를 한 저장소에서 다루지 않는다
- Supabase 프로젝트를 DYBROS 조직 안에 만들지 않는다
- 아미코를 Vercel에 배포하지 않는다 (DYBROS 전용 플랫폼)
- 로컬 트리를 섞지 않는다 (`~/amico/` vs `~/dev/`)
- 아미코 쪽에서 "DYLOOM" 이라는 말을 쓰지 않는다
