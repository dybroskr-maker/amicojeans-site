## 배치 1 — AMILOOM 자동화 설치 [T2]

`.github/workflows/` 3종과 규칙 파일을 **신규 작성**한다.

### 1-1. `gate.yml` — PR 필수 체크

이 저장소는 빌드가 없는 정적 HTML이다. 타입체크·번들 대신 아래를 검사한다.

- 모든 `.html` 파일이 파싱되는지 (파서는 devDependency 없이 Node 표준 또는 단일 npx 패키지로 해결)
- 인라인 `<script>` 블록의 문법 오류 (`node --check` 로 추출 검사)
- 내부 링크(`href="./..."`)가 실제 존재하는 파일을 가리키는지
- **금지 문구 검사**: `구파발` · `DIY Bros` · 다른 회사 자동화 명칭이 소스에 남아 있으면 실패

### 1-2. `agent-worker.yml` — 이슈 → 구현 → PR

- 트리거: `issues: [labeled]` — **`opened` 를 추가하지 않는다.** 생성 시 붙인 라벨도 `labeled` 를 쏘므로 같은 이슈로 두 번 돈다
- 라벨 `auto-t0` / `auto-t1` 만 점화한다
- 공식 Claude Code 액션 + `CLAUDE_CODE_OAUTH_TOKEN` 만 쓴다. API 키·서드파티 포크 액션 금지
- PR을 열되 **main에 직접 push하지 않는다** (머지 = Pages 배포이므로 머지가 배포 승인 지점이다)
- 워커 프롬프트에 금지 목록을 넣는다: `.github/workflows/**` 수정 금지, `survey.html` 수정 금지, 아래 「전역 금지」 전부

### 1-3. `agent-review.yml` — 검증 + 자동 머지

- 자동 머지 조건은 이 파일의 `automerge` 잡 **한 곳에서만** 정의한다
- 아래 파일·문구를 건드린 diff는 자동 머지에서 제외하고 PR을 draft로 내린 뒤 `needs-hub` 라벨을 단다
  - `.github/workflows/**`
  - `supabase/**` (아직 없음, 선반영)
  - 인증·세션·권한 관련 경로
  - 대외 공개 정보: 대표 이력 문장, 사무실 주소, 중국 사무소 표기, 거래처명, 단가

### 1-4. 규칙 파일

- `CLAUDE.md` — 이 저장소의 작업 규칙(단일 HTML 구조, 금지 목록, 티어 정책)
- `AGENTS.md` — AMILOOM 절차 정본(라벨 → 워커 → 리뷰 → 머지 → Pages)
- `.github/workflows/CLAUDE.md` — 워크플로 폴더 규칙(워커는 이 폴더를 고치지 않는다, `opened` 금지 근거)

### 1-5. 라벨

`auto-t0` · `auto-t1` · `needs-hub` 3종을 생성한다. 이미 있으면 색·설명만 맞추고 넘어간다.

### 1-6. 검증 (T2 · 3차 상한)

1. YAML 파싱 + `run:` 블록 `bash -n`
2. 시크릿이 없는 상태에서 `gate.yml` 만 PR로 1회 실행해 통과 확인

## 배치 2 — 공개 사이트 v0.3 (대표 설문 반영) [T1]

`index.html` 을 수정한다. 아래 12건이 전부이며, 이 목록에 없는 변경은 하지 않는다.

**먼저 「이미 있는 것」을 목록화하고, 없는 것만 만든다.** 히어로·컬렉션 그리드·프로젝트 타임라인·
브랜드 3탭·거래처룸 미리보기·핀 코멘트 리뷰 기능은 이미 있다. 재구현하지 않는다.

1. **사무실 주소 정정 (최우선)** — 소스 전체에서 `구파발` 을 제거한다.
   실제 주소는 `경기도 고양시 덕양구 동충로 70 (현대프리미어캠퍼스)` 이다.
   **표기 수준은 "경기 고양시 덕양구" 까지만** 노출하고, 전체 주소는 노출하지 않는다(예약자 안내용).
   쇼룸 명칭은 `구파발 쇼룸` → `고양 쇼룸` 으로 바꾼다. `docs/*.md` 안의 구파발 표기도 함께 고친다.

2. **홈 화면에서 컬렉션 사진 제거** — 홈의 컬렉션 섹션에서 이미지 카드를 없애고 **텍스트만** 남긴다.
   스타일명과 원단 표기를 목록/타이포 구성으로 배치한다. 홈에서 보이는 사진은 히어로 1장뿐이 되게 한다.

3. **히어로 사진 지정** — 히어로 자리표시자 라벨을 `워싱 원단 클로즈업` 으로 바꾼다. 사진은 아직 없다.

4. **헤드라인 강조점** — 「데님 한 종목만 한다」가 첫 화면의 주장이 되게 카피를 조정한다.
   현재 문구의 방향은 맞으므로 전면 교체가 아니라 강조 조정이다.

5. **메뉴에 「문의」 추가** — 컬렉션 · 프로젝트 · 브랜드 · **문의** + 거래처 로그인.
   문의 페이지 내용: 견적·생산 문의 안내, 연락처 자리, 문의 시 알려 주면 좋은 항목(품목·수량·시즌·희망 납기),
   쇼룸 방문 예약 안내. **폼 전송 기능은 넣지 않는다**(서버 없음). 연락처 노출 + 메일 링크로 한다.

6. **컬렉션을 로그인 전용으로 전환** — 메뉴는 유지하되, 비로그인 상태에서는 카드 대신
   「거래처 로그인 후 열람할 수 있습니다」 안내 화면 + 로그인 버튼을 보여준다.
   현재 컬렉션 카드 마크업은 삭제하지 말고 로그인 후 화면용으로 보존한다(주석 또는 비활성 영역).

7. **핏 가이드도 로그인 전용** — 브랜드 하위 「핏 가이드」 탭을 같은 방식의 안내 화면으로 바꾼다.
   핏 5종 구성과 치수표는 그대로 보존한다(대표가 5종 유지를 확정했다).

8. **상품 정보 표기 수준** — 로그인 후 화면 기준으로 **원단 중량·워싱까지** 적는다. 사이즈 스펙·거래처명은 적지 않는다.

9. **중국 사무소 표기** — 도시명을 노출하지 않고 `중국 생산 사무소` 로만 적는다. 소스 전체에서 도시명 제거.

10. **대표 이력 표기** — 학교명·연도를 적지 않는다. `이탈리아에서 패션을 공부했다` 수준으로만 남긴다.

11. **거래처룸 미리보기 문구** — 거래처에게 공개하는 범위를 `진행 상태 + 진행 사진 + 납기 일정` 으로 표기한다.
    원가·공장명은 계속 비공개다.

12. **글꼴 교체 가능 구조** — 서체를 CSS 변수 한 곳에서 바꿀 수 있게 정리한다.
    현재 값(`--disp` / `--body`)을 유지하되, 파일 상단에 「서체 교체 지점」 주석을 단다. 후보 서체를 추가하지는 않는다.

## 배치 3 — 3개국어 뼈대 [T1]

대표가 한국어 + 영문 + 중문을 요청했다.

- 화면 문구를 `i18n/ko.json` · `en.json` · `zh.json` 으로 분리하고 `index.html` 이 이를 읽어 렌더한다
- 언어 토글을 헤더 우측에 둔다. 선택은 `localStorage` 에 남긴다
- 기본 언어는 한국어. 첫 방문 시 브라우저 언어가 `zh` 계열이면 중문, `en` 계열이면 영문으로 시작한다
- **중문은 간체를 쓴다.** 번역 초안은 코드세션이 작성하되, 브랜드 문구는 직역하지 말고 의미 중심으로 옮긴다
- 고유명사 표기 고정: `AMICO JEANS` / `아미코진스` / `阿米可`(중문 병기가 필요한 경우에만)
- **번역 문구는 T0이 아니라 T1로 다룬다** — 대외 공개 문구이므로 게이트를 통과시킨다

`survey.html` 은 다국어화하지 않는다(역할이 끝난 페이지다).

## 배치 4 — 거래처룸 저장소 [T2 · 선행 조건 실측 후]

**먼저 실측한다.**
- 조직 `amicojeans` 가 존재하는가
- Supabase 프로젝트가 생성되어 있는가 (`SUPABASE_DB_URL` 시크릿 존재 여부로 판정)

**둘 중 하나라도 없으면 이 배치를 실행하지 않고, 무엇이 없어서 중단했는지만 보고한다.**
없는 상태에서 골격만 만들어 두면 나중에 경로가 어긋난다.

둘 다 준비되어 있으면:
- 저장소 `room` 을 만들고 정적 SPA 골격 + `supabase/0001_schema.sql` 을 넣는다
- 스키마와 RLS 정책은 이 저장소의 `docs/거래처룸_권한설계.md` 를 정본으로 삼는다.
  **단, 거래처 노출 범위는 대표 확정에 따라 「진행 상태 + 사진 + 납기」 까지다.** 문서와 다르면 대표 확정이 우선이다
- 오더 진행 단계는 4단계(샘플 → 확정 → 생산 → 출고)로 확정되었다
